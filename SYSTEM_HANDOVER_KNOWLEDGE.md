## 1. Core System Architecture

The CRM consists of three primary sheets:
1. **`Master Leads`**: The central lead database.
2. **`Members`**: The team roster containing agent names, total assigned leads, conversion rates, and unresolved pipelines.
3. **`Leads Summary`**: The date-filtered analytics dashboard containing performance and ROI tables.

## 3. Implemented Automation Logic (Google Apps Script)

All sheet automations are housed in [apps_script_v9.txt](file:///c:/Users/achir/Desktop/Lead%20tracking%20PS/apps_script_v9.txt). The core handlers include:

### A. Automatic F-Code and Timestamping (`onEdit`)
*   When a phone number is entered in Column B, the system normalizes it and performs a duplicate check.
*   If unique, it auto-assigns the next consecutive F-Code (starting at `F01000`) and stamps the current date.
*   If it is a duplicate, it skips code generation to maintain database integrity.

### B. Dynamic Team Roster Controller (`addNewMember` & `removeMember`)
*   **Insert Location**: New members are inserted **directly above the "TOTAL" row** in the `Members` sheet. 
*   **Format Retention**: The script copies formatting (background, text alignment, borders) from the row above it to prevent inheriting the dark navy styling of the TOTAL row.
*   **Sync**: Adding or removing a member automatically triggers the `refreshMemberDropdowns_()` helper, rebuilding the Column D dropdown validations down to row 1000 in real-time.
*   **Row Deletion**: Removing a member deletes the row completely to prevent leaving blank gaps that disrupt summation formulas.

### C. Row Warning Highlights (Conditional Formatting)
*   **Rule**: If a row has an F-code generated (meaning a lead exists), but **either** the **Status (Col F)** **or** **Campaign (Col I)** is left blank, the entire row highlights in light yellow (`#FFF9C4`).
*   **Real-time Update**: Runs natively in Sheets. Once both values are entered, the highlight clears immediately.

## 4. Rebuild Summary Dashboard (`rebuildLeadsSummarySheet`)

Running this script programmatically recreates the `Leads Summary` tab with four complex analytics tables:
*   **Table 1: All Leads**: Summarizes total leads by member and grade. Uses exact row counting (`COUNTIFS` on Col D) so multi-grade selections do not artificially double-count the total lead count.
*   **Table 2: Paid Leads**: Sums paid registrations. Uses `SUM` to capture multi-grade registrations.
*   **Table 3: Unresolved Pipeline**: Calculates active leads (`New`, `Contacted`, `No Answer`, `Interested`, and `Other Pending`).
    *   *Bug Fix*: Dead-end statuses (`Off`, `Invalid`, `Wrong number`) are explicitly subtracted from "Other Pending" so they do not inflate the pipeline.
    *   *Bug Fix*: Total row uses `totRow1` instead of `totRow3` to avoid circular `#REF!` errors.
*   **Table 4: Campaign ROI**: Automatically scans Column I (`Campaign / Boost`) of the `Master Leads` sheet, extracts unique campaigns, sorts them alphabetically, and builds performance records dynamically.

## 5. Critical Guidelines for Future Upgrades

1.  **#REF! Prevention**: Always use `INDEX(Sheet!$A:$A, row)` instead of direct sheet cell links (like `Sheet!A10`) when referring to dynamic tables. Direct links break and turn into `#REF!` if rows are deleted.
2.  **Validation Ranges**: Re-run the **Fix Column Dropdowns** function whenever you modify constant options (like adding new statuses) to push updates safely to all cells without touching existing data.
